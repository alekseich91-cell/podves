# PDF Export — Design Spec

**Дата:** 2026-05-11
**Статус:** черновик, ожидает ревью

## 1. Цель

Дать пользователю возможность экспортировать готовый rigging-план в PDF: схему грида + табличный отчёт по точкам подвеса. Документ должен годиться для печати на A4 и для отправки заказчику/в продакшн.

## 2. Область (scope)

### Входит:
- Кнопка «Экспорт PDF» в тулбаре (рядом с «Сохранить .json»).
- Открытие отдельной вкладки браузера с предварительным просмотром отчёта.
- В отчёте: шапка, схема грида, таблица точек подвеса, сводка.
- Print-стили под A4 landscape.
- Кнопка «Печать / Сохранить в PDF» в превью, скрытая при печати.

### Не входит:
- Свой PDF-движок (jsPDF и т.п.) — используем браузерную печать.
- Кастомизация шаблона отчёта пользователем (поля, шрифты, логотип).
- Многоязычность вне русского.
- Экспорт схемы без отчёта или наоборот — в MVP один шаблон.

## 3. UX-поток

1. Пользователь жмёт «Экспорт PDF» в тулбаре.
2. Открывается новая вкладка с готовым отчётом.
3. Сверху отчёта — кнопка «Печать / Сохранить в PDF», по клику — `window.print()`.
4. В диалоге печати браузера пользователь выбирает «Сохранить как PDF» или печатает на принтере.
5. Закрытие вкладки возвращает в редактор без потерь.

Открытие новой вкладки происходит синхронно внутри `click`-хендлера — это считается user gesture, pop-up blocker такое не режет.

## 4. Архитектура

Новый изолированный модуль в `src/export/`. Не лезет в редактор и редактор не знает о нём ничего, кроме точки входа.

### 4.1 Структура модуля

```
src/export/
  print.js          — точка входа: openPrintView(project, report)
  print_svg.js      — renderPrintSvg(project, report) → SVG-строка
  print_html.js     — renderPrintHtml(project, report) → полная HTML-страница
  print_styles.js   — PRINT_STYLES: строковая константа с CSS
```

Разделение по файлам, потому что:
- `print_svg` — содержит геометрию и стилизацию (~150 строк),
- `print_html` — таблицы и шапка (~100 строк),
- `print_styles` — CSS (~80 строк),
- `print.js` — оркестрация (~30 строк).

Каждый файл — одна понятная ответственность, тестируется независимо.

### 4.2 Точка входа

Используем `Blob` + object URL вместо `document.write()` — это безопасно (исключает риск XSS через document.write) и работает синхронно из click-хендлера:

```js
// src/export/print.js
export function openPrintView(project, report) {
  const html = renderPrintHtml(project, report);
  const blob = new Blob([html], { type: "text/html" });
  const url = URL.createObjectURL(blob);
  const win = window.open(url, "_blank");
  // URL живёт до закрытия вкладки; освобождаем через setTimeout,
  // чтобы вкладка успела загрузиться.
  setTimeout(() => URL.revokeObjectURL(url), 60_000);
}
```

### 4.3 Экранирование пользовательских строк

В HTML попадают пользовательские поля: имя проекта, названия типов приборов. Все они должны прогоняться через утилиту `escapeHtml(str)` (заменяет `& < > " '`), прежде чем подставляться в шаблон. Утилита живёт в `print_html.js`.

### 4.4 Подключение в тулбаре

В `src/toolbar.js` добавляется кнопка «Экспорт PDF», по клику вызывает `openPrintView(ctx.project, ctx.report)`. Для этого `renderToolbar` начинает получать `report` целиком вместо `totals`:

- Сейчас в `main.js`: `renderToolbar(toolbarHost, { project, view, totals: report.totals }, …)`.
- Станет: `renderToolbar(toolbarHost, { project, view, report }, …)`. Внутри тулбара существующая строка про общий вес читает `ctx.report.totals.totalWeight`.

## 5. Содержимое отчёта

### 5.1 Шапка

Одна горизонтальная полоса:

- Слева крупно: название проекта.
- Справа мелко: дата экспорта (ISO, локальная), общий вес «кг», количество точек подвеса, ферм, приборов.

### 5.2 Схема (центральный блок)

SVG, занимает ~60% высоты листа, центрирована, viewBox автоматически рассчитан по габаритам грида с отступами 10% по краям. Позиции точек подвеса и приборов резолвятся через существующий `anchorPosition(grid, anchor)` из `src/physics/geometry.js`. Y инвертируется при переводе из мировых координат в SVG (как в редакторе), чтобы «верх» проекта оказался сверху листа.

Рендерится `renderPrintSvg`:

- **Сегменты ферм** — чёрные линии толщиной 2px, рядом длина в метрах (`L.LL м`) мелким курсивом серого цвета.
- **Узлы** — чёрные точки радиуса 3px.
- **Точки подвеса** — квадрат 14×14px чёрной обводкой 1.5px, внутри номер (порядковый, 1..N). Координата квадрата — центр точки подвеса в мировых координатах.
- **Лебёдки** — кружок диаметром 12px с буквой «M» внутри.
- **Приборы** — точки радиуса 4px со штатной чёрной заливкой; рядом подпись с первой буквой названия типа (детерминированно из `type.name`). У модели `FixtureType` поля цвета нет (`{ id, name, weight }`), поэтому различение по типу — только через буквенный лейбл. Легенда типов — отдельный список под схемой, если приборы есть: «А — PAR64 (3 кг)», «Б — Movinghead (12 кг)» и т.д.
- **Перегрузка / предупреждение** по статусу из `report.pointLoads[i].status` (`"ok"` / `"warn"` / `"over"`):
  - `"ok"` — обычная чёрная обводка.
  - `"warn"` (≥70 % worst-case к лимиту) — обводка пунктиром (`stroke-dasharray`), толщина та же.
  - `"over"` (worst-case > лимита) — обводка 2.5px красного цвета (`#c00`). На ч/б принтере остаётся жирной линией.

Никакой подсветки выделения, никаких hover-стилей, никаких сеток. Чистая чёрно-белая схема + красный для критики.

### 5.3 Таблица точек подвеса

Под схемой. Колонки:

| № | X, м | Y, м | Нагрузка, кг | Worst-case, кг | Лимит, кг | Статус |
|---|------|------|--------------|----------------|-----------|--------|

- Номер строки соответствует номеру в квадратике на схеме.
- Координаты с точностью до 0.01 м.
- Нагрузки округлены до целых кг.
- Статус берётся напрямую из `report.pointLoads[i].status`:
  - `"ok"` → «OK».
  - `"warn"` → «Внимание» (worst-case ≥ 70 % от лимита).
  - `"over"` → «Перегруз» (worst-case превышает лимит).
- Перегруженные строки — жирным начертанием.

Строки имеют `break-inside: avoid` для аккуратных переносов.

### 5.4 Сводка

Ниже таблицы:

- Общий вес конструкции: X кг.
- Самая нагруженная точка: №N — Y кг.
- Худший worst-case: №M — Z кг.
- Если `report.warnings` непуст — список предупреждений из него выводится прямо в сводку (`compute()` уже формирует тексты предупреждений на русском, переиспользуем их as-is).

### 5.5 Кнопка управления (только на экране)

В правом верхнем углу превью:

```html
<button onclick="window.print()">Печать / Сохранить в PDF</button>
```

Стилизуется через CSS, при `@media print` имеет `display: none`.

## 6. Print-стили

`PRINT_STYLES` содержит:

```css
@page { size: A4 landscape; margin: 10mm; }
body { font-family: system-ui, sans-serif; color: #000; background: #fff; }
.print-controls { position: fixed; top: 8px; right: 8px; }
@media print {
  .print-controls { display: none; }
}
table { border-collapse: collapse; width: 100%; font-size: 11px; }
th, td { border: 1px solid #888; padding: 3px 6px; text-align: left; }
tr { break-inside: avoid; }
.overloaded { font-weight: bold; color: #c00; }
.scheme { width: 100%; max-height: 60vh; }
```

Шрифты — системные. Цвета — чёрный + красный для критики. Размеры подобраны под landscape A4 (~270×190 мм usable area).

## 7. Многостраничность

Один лист — типичный случай (схема + 5–10 точек). При большем числе точек таблица переносится на вторую страницу через `break-inside: avoid` у `<tr>`. Схема всегда на первой странице (`break-after: auto`).

## 8. Тестирование

- **Юнит-тесты** на `renderPrintSvg` и `renderPrintHtml`: сгенерировать на нескольких фикстурах (одна точка, перегруз, изолированный сегмент, моторы), проверить наличие ключевых элементов в выводе (по подстрокам/regexp). Тесты на `node --test` без браузера — функции возвращают строки.
- **Тест на экранирование**: проект с именем `<script>alert(1)</script>` → проверить что в HTML экранирован.
- **Ручная проверка** в Chrome/Safari/Firefox:
  - Превью открывается в новой вкладке.
  - Кнопка печати работает.
  - В диалоге печати landscape выставлен по умолчанию.
  - PDF выглядит читаемо: схема, таблица, шапка.
- Линтер/тайпчек отсутствуют в проекте — следуем существующему стилю.

## 9. Ограничения / открытые вопросы

- **Pop-up blocker.** При вызове из user gesture (click) — не блокируется. Если в редких браузерах блокируется — пользователь видит подсказку браузера и разрешает; альтернативный fallback не делаем в MVP.
- **Очень большие гриды.** Если габариты грида > 50 м, мелкий текст подписей становится нечитаемым. Принимаем как ограничение MVP. В будущем — масштабирование подписей или режим «несколько листов».
- **Иконки приборов.** Если в палитре много типов с похожими цветами — на ч/б принтере неразличимы. В MVP даём цвет + букву типа (первая буква названия). Полноценные shape-различия — задел на будущее.
